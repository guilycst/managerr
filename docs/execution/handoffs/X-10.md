## Product result

Product commit: `915eaab2568394ae4afb2ab0e580e8db9936fec8` (`feat(qbittorrent): add standalone read client`).

The new independent module has module path
`github.com/guilycst/mastarr/clients/qbittorrent`. Its only non-standard
dependency is the generated oapi-codegen runtime; it imports no Mastarr root,
domain, port, storage, workflow, adapter or infrastructure package.

`openapi.yaml` is a Mastarr-owned, versioned compatibility contract for
qBittorrent 5.0+ and WebAPI 2.x. It contains only the read surface plus cookie
login: application version, WebAPI version, torrent inventory, generic torrent
properties, torrent files, categories and tags. Object schemas reject unknown
fields, operation methods are GET except for the explicitly documented login
POST, and no OpenAPI security scheme is declared. Examples and fixtures use
synthetic values. The contract records the pinned qBittorrent 5 WebUI API page
evidence from `docs/research/upstream-evidence.md`.

The handwritten client owns cookie login, SID session state, origin
`Origin`/`Referer` headers, context-bound requests, same-origin safety by
rejecting redirects, bounded response reads, strict JSON decoding and
normalization into standalone DTOs. Login verifies the exact successful `Ok.`
body because qBittorrent can return HTTP 200 for failed credentials. Each
client receives an isolated cookie jar. Errors are typed and sanitized by
`UpstreamError`; status/body text, URLs and credentials are not copied into
error messages. The read client preserves qBittorrent timestamps, counters and
`-1` unknown sentinels, validates file piece ranges and rejects over-limit
arrays without truncation.

Generated `generated/client.gen.go` was produced by the pinned
`github.com/oapi-codegen/oapi-codegen/v2` v2.8.0 tool from the module-local
contract. `generate.go` carries the reproducible `go:generate` command and
`check-generation.sh` regenerates in a temporary directory and compares the
committed output.

Synthetic `httptest` coverage exercises successful cookie auth, invalid-body
and forbidden login failures, both version probes, all read DTOs and query
options, normalization and copy isolation, unknown fields, malformed JSON,
oversized bodies, item bounds, rate limits, endpoint validation, context
cancellation, transport timeout and cross-origin redirect rejection. The
handler records that login is the only POST made by the client.

## Acceptance contribution and review risks

- A-04: the module retains the upstream hash and complete torrent/file
  observations. Connection-scoped persistence identity remains the X-12/root
  adapter responsibility because this independent client deliberately has no
  Mastarr domain dependency.
- A-09: each client instance has an isolated SID jar and never shares session
  state. Cross-instance persistence identity and configured connection IDs are
  still supplied by the root translation boundary.
- A-28: state, progress, completion timestamps, seeding and upload-rate
  evidence are read and preserved. The module does not infer stopped state from
  zero upload speed and exposes no stop or other control route.
- A-45: generated output, pinned tool invocation, module-local reproducibility,
  GOWORK-off tests/race/vet/module verification and root guardrail evidence are
  present. Full repository acceptance remains a coordinator integration gate.

No live qBittorrent instance, credential, tracker coordinate, media payload,
upstream mutation, filesystem mutation, release or deployment was used.

The compatibility candidate has not been exercised against a selected product
build, so future qBittorrent fields or version-specific omissions may require a
contract revision. The `/torrents/info` endpoint returns an upstream array;
this module passes qBittorrent's limit/offset filters through and bounds one
response but does not invent a cursor, snapshot or revalidation protocol.
Descriptor export, native stop/read-back, relocation/rename/deletion and
connection-scoped Mastarr translation remain outside X-10. X-12 is the next
migration step and must consume this module through a published module
dependency, without a local replace directive or generated-type leakage into
the root adapter.
