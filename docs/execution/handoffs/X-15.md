## Product result

Product commit: `8a11bea1003b50d00d57318244a4bca8b138397b`
(`feat(sonarr): add standalone read client`). The commit adds one independent
Go module at `clients/sonarr` and does not modify the root module, adapters,
execution state, task plan, UI, or another client module.

The Mastarr-owned `openapi.yaml` is OpenAPI 3.1.1 and freezes a narrow Sonarr
v3 read contract:

- `GET /api/v3/system/status` for typed version and status evidence;
- `GET /api/v3/series` and `GET /api/v3/series/{id}` for catalog records;
- `GET /api/v3/rootfolder` and `GET /api/v3/qualityprofile` for options;
- `GET /api/v3/episode` with an explicit `seriesId` and
  `includeEpisodeFile` query value;
- `GET /api/v3/episodefile` scoped to a series;
- `GET /api/v3/manualimport` for the native, read-only manual-import preview.

The generated oapi-codegen v2.8.0 output is committed at
`clients/sonarr/internal/generated/client.gen.go`. The generated package is
module-internal, and the handwritten client maps generated DTOs into its own
exported observations. No generated upstream type, Sonarr API object, or
client import crosses into the Mastarr root domain or public API. The module
contains no registration, manual-import execution, command, search, or other
write method; that is a later reviewed extension.

The handwritten transport validates absolute HTTP/HTTPS endpoints and literal
reverse-proxy prefixes, rejects credentials/query/fragment/ambiguous path
syntax, clones the injected HTTP client, disables cookie persistence and
rejects redirects. It applies API-key authentication through `X-Api-Key`,
per-request context deadlines (15 seconds by default), bounded response reads,
status-first HTTP normalization, and sanitized typed `UpstreamError` values.
`Client.String()` and failures omit the API key and upstream body text.

Sonarr full-array endpoints are represented by a bounded `Page[T]` with
complete coverage and an empty `NextCursor`. The client retains the whole
accepted array before claiming complete coverage; an over-bound response is
rejected instead of silently truncating records or inventing continuation
semantics for an endpoint with no native cursor contract. Required identity
and path fields, duplicate IDs, episode/series scope, nested episode-file ID
agreement, duplicate JSON members, invalid UTF-8, trailing JSON and bounded
native strings are checked. Unknown upstream fields remain only in generated
compatibility DTO storage for forward compatibility and are not copied into
normalized public observations.

Manual-import candidates retain typed series and exact episode references,
season and absolute numbering, episode-file IDs, quality/revision data,
language data, release/download fields, subtitle flag aliases and rejection
evidence. The module does no subtitle pairing or filesystem/path mapping.
`PreviewManualImport` sends only the native GET and requires an explicit
folder; optional series and download IDs are validated and sent as query
parameters.

Synthetic `httptest` fixtures cover API-key and reverse-proxy request shape,
status/version reads, catalog and option observations, episode-file inclusion
and identity mismatch, full-array coverage, native preview query and typed
nested evidence, malformed/duplicate/missing JSON, oversized responses,
status-first unauthorized classification, redirects, deadlines, invalid
configuration, invalid request no-network behavior and normalized output that
does not leak arbitrary generated properties.
