## Contract and work

- Linked specifications: X-04 in `docs/plans/implementation.md`; Jellyfin and Seerr sections in `docs/specs/spec-001-media-reconciliation/connectors.md`; acceptance cases A-08, A-09, A-54 and A-55; the C-03 domain and ports contract. The implementation preserves the read-only discovery boundary, scoped identities, partial coverage and independent upstream evidence rules.
- Product implementation is committed at `82a8a80b05cd150716dcdc1f41965f30148cbbdc` (`feat(connectors): add Jellyfin and Seerr read adapters`).
- Jellyfin `read.Client` implements the media-server read, refresh-observation and capability ports. It reads version metadata, libraries, paginated items, item details, provider IDs and media sources using GET requests. Item availability is derived from playable media-source evidence and path mappings; a path-only item is retained as evidence, and unmapped or ambiguous paths remain unavailable/unresolved. Connection and optional user scope are validated before requests. Item/list pagination has signed opaque cursors, bounded response/page/item counts, snapshot digest evidence and explicit partial reasons. The refresh operation is deliberately read-only and returns a typed unsupported result with evidence because no tested refresh capability is claimed.
- Jellyfin path mapping accepts only normalized absolute paths and component boundary matches, rejects traversal, aliases and malformed paths, and supports the Windows root form. The adapter never performs filesystem or upstream writes.
- Seerr `Client` implements request-catalog reads and capabilities only. It reads `/api/v1/status`, `/api/v1/media` and `/api/v1/request` with `take`/`skip` pagination and preserves native media/request statuses, names, source timestamps, provider IDs/relationships, service relationships, Jellyfin IDs, rating keys, 4K variants, seasons, tags and service errors. Media and request observations retain independent availability and native state, so partial, pending, processing, approved, failed and completed states are not collapsed into a boolean.
- Seerr pages use bounded signed cursors, page-info validation, duplicate/overlap detection, response-size and record limits, and explicit partial coverage for missing or inconsistent pagination evidence. Empty pages with Seerr's valid `pages: 0` shape are accepted as complete. Invalid identities, malformed data, timeouts, unauthorized responses and unsupported status routes produce scoped typed results without proving absence. The read adapter exposes no request or mutation method; `seerr.writes` is explicitly unsupported.
- Upstream IDs remain raw in the common records for compatibility with the existing Arr/qBittorrent conventions, while detailed observations expose `connection-id:ID` scoped identities for A-09 persistence and correlation. Provider and service relationships preserve the originating component/slot rather than guessing a single owner.
- Synthetic fixtures at `tests/fixtures/catalogs/` cover Jellyfin version/libraries/items, path-only playable evidence, mapping failures, Seerr status, multi-page media and request lists, native statuses, providers, service relationships, 4K fields, nested availability, timestamps, tags, errors, overlap and malformed/empty/bounded responses. They contain no credentials, private coordinates, tracker data, real inventories or media payloads.
- No shared contract change was requested. Real upstream product-version support remains an integration concern; the adapters report unknown/unsupported explicitly when the tested endpoint or capability is unavailable.
