## Product result

Product commit: `3823f66eaca1796457d7dc9efa93d2ccf5b6bc67`
(`feat(radarr): add standalone read client`). The product adds one independent
Go module at `clients/radarr` and does not modify the root module, adapters,
execution state, task plan, UI, another client module or shared scripts.

The Mastarr-owned `openapi.yaml` is OpenAPI 3.1.1 and freezes a narrow Radarr
v3 read contract:

- `GET /api/v3/system/status` for typed version and status evidence;
- `GET /api/v3/movie` and `GET /api/v3/movie/{movieId}` for the catalog;
- `GET /api/v3/rootfolder` and `GET /api/v3/qualityprofile` for options;
- `GET /api/v3/moviefile?movieId=...` for movie-file observations;
- `GET /api/v3/manualimport` for the native, read-only manual-import preview.

The generated oapi-codegen v2.8.0 output is committed at
`clients/radarr/internal/generated/client.gen.go`. The generated package is
module-internal, and the handwritten client maps generated DTOs into its own
exported observations. No generated upstream type, Radarr API object or
client import crosses into the Mastarr root domain or public API. The module
contains no registration, manual-import execution, command, search, lookup or
other write method; those require a later reviewed extension.

The handwritten transport validates absolute HTTP/HTTPS endpoints and literal
reverse-proxy prefixes, rejects credentials/query/fragment/ambiguous path
syntax, clones the injected HTTP client, disables cookie persistence and
rejects redirects. It applies API-key authentication through `X-Api-Key`,
per-request context deadlines (15 seconds by default), bounded response reads,
status-first HTTP normalization and sanitized typed `UpstreamError` values.
`Client.String()` and failures omit the API key and upstream body text.

Radarr full-array endpoints are represented by a bounded `Page[T]` with
complete coverage and an empty `NextCursor`. The client retains the whole
accepted array before claiming complete coverage; an over-bound response is
rejected instead of silently truncating records or inventing continuation
semantics for a native endpoint with no cursor contract. Required identity and
path fields, duplicate IDs, movie/movie-file scope, nested movie-file identity,
duplicate JSON members, invalid UTF-8, trailing JSON and bounded native text
are checked. Unknown upstream members remain only in generated DTO storage for
forward compatibility and are not copied into normalized public observations.

Manual-import candidates retain exact paths, sizes, movie and movie-file
identity, typed quality/language/release fields and native rejection evidence.
`PreviewManualImport` is the downloaded-folder mode and rejects a supplied
movie ID before network dispatch; `PreviewLibraryImport` and its explicit
`PreviewMovieImport` alias send only a movie ID and verify every returned movie
association. Both methods perform only the native GET and never execute an
import. The module does no subtitle pairing or filesystem/path mapping.

Synthetic `httptest` fixtures cover API-key and reverse-proxy request shape,
status/version reads, movie catalog and options, movie-file inclusion and
identity mismatch, complete-array coverage, native folder and library preview
queries, typed nested evidence, malformed/duplicate/missing JSON, oversized
responses, status-first unauthorized classification, redirects, deadlines,
invalid configuration, invalid request no-network behavior and normalized
output that does not leak arbitrary generated properties.
