## Finding

### P1: index membership and working-tree checks do not validate the staged commit tree

The new Git check uses only:

```sh
git ls-files --error-unmatch -- sqlc.yaml
```

An intent-to-add entry satisfies that membership query even though Git omits
the path from the tree written from the index. The following disposable state
was built from the exact product:

```text
index entry: 100644 e69de29bb2d1d6434b8b29ae775ad8c2e48c5391
flags: intent-to-add
git status: DA sqlc.yaml
git diff --cached: D sqlc.yaml
```

The working-tree `sqlc.yaml` remained valid. `generate.sh --check`, the
pre-commit hook and `check-guardrails.sh --ci` all returned zero. Running
`git write-tree` then produced a tree with no `sqlc.yaml`. The full aggregate ended
with `guardrail checks passed (ci)`, proving the issue is not limited to one
entry point.

The same commit-candidate mismatch affects generated outputs. In separate
disposable repositories, stale sentinels were staged in:

```text
internal/storage/sqlc/query.sql.go
clients/qbittorrent/generated/client.gen.go
```

The working copies were then restored to the exact generated bytes without
altering the index. Git reported `MM`; the index retained each sentinel and the
working tree did not. Both `generate.sh --check` and the pre-commit hook
returned zero. The hook therefore approved stale generated content that its
working-tree comparison never examined.

As a control, when stale SQLC bytes remained in both index and working tree,
pre-commit returned one and changed neither. All ordinary missing, stale and
extra output probes also fail cleanly. The remaining defect is specifically
the binding between the validated filesystem state and the staged tree.

Contract: C-05 requires committed generated output to be reproducible, A-45
requires clean regeneration, and the dispatch explicitly requires staged
SQLC deletion and prior staged-output regressions to fail. A successful
pre-commit result must describe the content Git will commit.

Required correction: validate the staged tree itself, or reject index/worktree
divergence for every authoritative generator input and generated output before
reporting success. Detection must cover intent-to-add entries, staged deletes,
staged stale/missing/extra generated files, and partially staged generator
inputs. Add regressions that inspect `git write-tree`, not only working-tree
existence and hashes. Preserve the existing non-Git archive behavior.
