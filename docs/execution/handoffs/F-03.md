- Product implementation: `50e5a3a32e2acf975e3c489e4c75839a0d73a87e` (`feat(scanning): add durable scan scheduler`).
- Added a storage-neutral `StateStore` seam and immutable `Snapshot` projection for configured roots and scans. The scheduler can be mapped to the root-owned SQLite `scans` and `coverage_snapshots` records without importing storage or infrastructure packages. `MemoryStore` is a concurrency-safe synthetic implementation for tests and small embedders.
- Added validated per-root interval schedules with the documented thirty-second default minimum, deterministic ticking, disabled periodic schedules, root retirement, retained scan history and revision binding. Reconfiguration retires removed roots and never deletes their scan evidence.
- Added manual admission with one active scan per root and exactly one coalesced follow-up. Repeated triggers while queued or running do not grow the queue; a waiting retry/continuation is accelerated in place. Per-root periodic and manual work share the same concurrency bound.
- Added bounded execution controls: configurable maximum concurrent runners, per-run timeout, cancellation propagation, bounded opaque cursor and error detail sizes, cooperative shutdown, and explicit retry backoff through `ErrRetryable`. Runner panics and context outcomes become sanitized durable terminal states.
- Added durable progress callbacks. Each checkpoint persists cursor, observed count, aggregate coverage and per-source coverage before the runner can continue. Restart recovery converts abandoned running scans to queued recovery work with the saved checkpoint; waiting scans preserve their cursor and backoff across restart.
- Added evidence rules that keep complete, partial and unknown coverage distinct. Incomplete or missing source evidence downgrades aggregate completeness, and only a succeeded scan with complete aggregate and non-empty complete source evidence can assert absence. A later partial/unknown scan updates `LastCoverage` while retaining `LastCompleteCoverage`.
- Added detached read methods (`Snapshot`, `Root`, `Scan`, `ListScans`) and deep cloning of nested coverage slices and timestamp pointers so API/read consumers cannot mutate scheduler state.
- Discovery and client readers remain runner-owned and read-only. This lane does not register titles, write upstream services, alter categories/tags, transfer files, or expose private paths. A production root adapter and scanner runner remain coordinator-owned downstream integration work.
