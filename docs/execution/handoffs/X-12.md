## Contract and implementation

- Linked specification and plan: X-12 in `docs/plans/implementation.md` and
  `docs/execution/tasks.json`; qBittorrent read compatibility contract in
  `clients/qbittorrent/openapi.yaml` and `clients/qbittorrent/README.md`; the
  connection-scoped identity, unknown-evidence and read-only invariants in
  `AGENTS.md` and the media reconciliation specification.
- `Client` now constructs the standalone qBittorrent client and uses its typed,
  bounded, strict read surface for application/WebAPI versions, torrent
  inventory, torrent properties and torrent files. The adapter translates
  standalone `UpstreamError` values into `domain.UpstreamError` values without
  copying upstream bodies, credentials, endpoint coordinates or generated DTOs.
- The standalone `Torrent`, `TorrentProperties`, and `TorrentFile` values are
  translated immediately into the adapter's local summaries and `FileObservation`
  values. No generated or standalone DTO is present in a port signature,
  observation, cursor, or package-level exported type. Existing path mappings,
  exact root-relative payload targets, signed cursor pagination, overlap checks,
  bounded revalidation and partial-coverage reasons remain adapter-owned.
- Connection-scoped `ExternalID`/`ScopedIdentity`, qBittorrent state/progress,
  seeding counters, completion/addition timestamps, category/tags, content and
  save paths, and file metadata remain available to existing Mastarr ports.
  Legacy v1/v2 identity fields and the historical file-seed evidence used by the
  root contract are retained in a bounded local response capture; only those
  adapter-owned compatibility fields are removed before strict native decoding.
  Unknown native fields, missing required native fields, duplicate members,
  malformed JSON, invalid UTF-8, invalid identities and over-limit responses
  still fail closed through the standalone client. The compatibility projection
  returns malformed/invalid bytes unchanged and only rewrites responses that
  contain explicitly supported legacy fields.
- Descriptor export remains a separate root-adapter best-effort capability. The
  standalone module intentionally freezes only its documented read routes and
  does not expose descriptor export. The existing root-only export probe still
  verifies bencode structure, binds the digest to a v1/v2 identity, stores only
  metadata, and never exposes descriptor bytes in ordinary observations. It
  uses the adapter's isolated descriptor HTTP session; this can result in a
  second login when descriptor mode is enabled and is recorded as a review risk.
- The adapter exposes no qBittorrent control route or mutation. The standalone
  client issues one login POST and GET-only reads; descriptor export is GET-only.
  Stop/read-back, relocation, rename and metadata removal remain X-07 scope.
- Synthetic fixtures were brought up to the standalone contract's required
  inventory/properties/file members, including nonnegative piece ranges, while
  retaining legacy identity and seed evidence for adapter translation. The
  malformed fixtures remain intentionally malformed for negative coverage.

## Acceptance contribution and review risks

- A-04: v1/v2 hash identities remain bound to the qBittorrent connection
  through `ScopedIdentity`; descriptor identity matching and history/pagination
  evidence remain distinct from current observations.
- A-09: connection IDs and per-instance private native sessions are retained;
  two clients cannot reuse one SID or collide persistence identities. The
  standalone client's generated types remain below the adapter translation
  boundary.
- A-28: inventory records preserve progress, state, completion time, seeding
  counters, file availability and read-only behavior. This lane does not claim
  stopped state from zero upload speed and does not implement control writes.

The native module's published contract excludes descriptor export and some
legacy qBittorrent fields. The adapter keeps a bounded local compatibility
capture for descriptor identity and file seed observations, and uses a separate
root-owned descriptor session. An upstream product response that omits a
contract-required native member remains unknown/failed rather than being
fabricated. A live qBittorrent product-version compatibility run is still an
external evidence gate.
