## Product result

`internal/filesystem/organize` now provides an independent filesystem action
implementation with explicit same-filesystem and cross-filesystem semantics.

- `Move` and `Rename` validate exact root-relative manifests, reject configured
  read-only sources or destinations, and verify source identity and exact
  directory children immediately before publication. Linux first transfers the
  selected entry into an operation-private quarantine and validates that inode
  before publishing; regular files publish from the retained descriptor with
  `AT_EMPTY_PATH`, while directories use no-replace publication from the
  private quarantine. They sync both parent directories and perform destination
  identity/read-back plus old-path absence checks. Existing target content
  remains a conflict; cross-device moves return `ErrCrossDevice` before
  mutation. A pathname exchange after public preflight therefore cannot move an
  unapproved replacement.
- `Delete` is explicit permanent deletion. It accepts only exact identity-bound
  manifests, rejects root targets, traversal, symlinks, special files and
  changed directory child sets, revalidates immediately before mutation, then
  quarantines the selected inode before recursive removal. The quarantine is
  identity-checked and the original path is restored when the approved object
  is no longer present. It syncs each affected parent and verifies selected
  paths are absent. Missing paths are already satisfied. Partial directory
  effects return the affected entries and an uncertain/reviewable error rather
  than expanding scope.
- `CopyVerifyDelete` and `MoveAcrossDevices` are separate APIs and request
  types. They require strong copy digests, prove different filesystem devices,
  delegate copy/hardlink placement to the reviewed F-04 implementation, run
  read-only copy reconciliation, and create an operation-owned destination
  protection witness before deleting the approved source. The witness is
  revalidated before and after source removal; if the destination disappears,
  the source remains or the verified destination is restored from the witness.
  A missing source with a digest-matching destination is already satisfied,
  which makes a completed composition safe to repeat after a lost response.
- `ReconcileMove`, `ReconcileRename` and `ReconcileDelete` are read-only
  recovery paths. No automatic retry or linked download-client action is
  included. Trash and restore remain unsupported in this lane.
- Linux uses descriptor-relative `openat`/`fstatat` with `O_NOFOLLOW`,
  `RENAME_NOREPLACE`, descriptor-bound regular-file links, and explicit device
  identity checks. The constructor rejects equal, nested, symlink-alias and
  other physically conflicting configured roots. Darwin and other platforms
  compile and report `ErrUnsupported` for organize writes until reviewed
  target-specific no-follow/no-replace/delete primitives exist.

All fixtures use temporary roots and synthetic bytes. No credentials, live
services, private coordinates, real inventories or user media were used.
