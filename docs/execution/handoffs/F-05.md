## Product result

`internal/filesystem/organize` now provides an independent filesystem action
implementation with explicit same-filesystem and cross-filesystem semantics.

- `Move` and `Rename` validate exact root-relative manifests, reject configured
  read-only sources or destinations, verify source identity and exact directory
  children immediately before publication, create destination parents through
  descriptor-relative no-follow traversal, and publish with Linux
  `renameat2(RENAME_NOREPLACE)`. They sync both parent directories and perform
  destination identity/read-back plus old-path absence checks. Existing target
  content remains a conflict; cross-device moves return `ErrCrossDevice` before
  mutation.
- `Delete` is explicit permanent deletion. It accepts only exact identity-bound
  manifests, rejects root targets, traversal, symlinks, special files and
  changed directory child sets, revalidates immediately before removal, syncs
  each affected parent, and verifies selected paths are absent. Missing paths
  are already satisfied. Partial directory effects return the affected entries
  and an uncertain/reviewable error rather than expanding scope.
- `CopyVerifyDelete` and `MoveAcrossDevices` are separate APIs and request
  types. They require strong copy digests, prove different filesystem devices,
  delegate copy/hardlink placement to the reviewed F-04 implementation, run
  read-only copy reconciliation, then separately delete the approved source.
  Source-removal failure leaves the verified destination in place. A missing
  source with a digest-matching destination is already satisfied, which makes a
  completed composition safe to repeat after a lost response.
- `ReconcileMove`, `ReconcileRename` and `ReconcileDelete` are read-only
  recovery paths. No automatic retry or linked download-client action is
  included. Trash and restore remain unsupported in this lane.
- Linux uses descriptor-relative `openat`/`fstatat` with `O_NOFOLLOW`,
  `RENAME_NOREPLACE`, and explicit device identity checks. Darwin and other
  platforms compile and report `ErrUnsupported` for organize writes until
  reviewed target-specific no-follow/no-replace/delete primitives exist.

All fixtures use temporary roots and synthetic bytes. No credentials, live
services, private coordinates, real inventories or user media were used.
