## Product result

Product commit: `3fce4c79f4e52ba3147f300e8a460e9e44c228bc`
(`feat(qbittorrent): add guarded control routes`).

The independent qBittorrent compatibility contract now includes the narrow
control surface reached by X-07:

- `POST /api/v2/torrents/stop` with `hashes`;
- `POST /api/v2/torrents/setLocation` with `hashes` and the qBittorrent
  containing download `location` directory;
- `POST /api/v2/torrents/renameFile` with `hash`, `oldPath` and `newPath`;
- `POST /api/v2/torrents/renameFolder` with `hash`, `oldPath` and `newPath`;
- `POST /api/v2/torrents/delete` with `hashes` and `deleteFiles` frozen to
  `false`.

The OpenAPI compatibility document remains Mastarr-owned and versioned for
qBittorrent 5.0+ / WebAPI 2.x. Generated request models, form builders and
response wrappers were regenerated from that document with pinned
oapi-codegen v2.8.0. `generated/client.gen.go` is committed generated output;
it was not hand-edited. `generate.go` and `check-generation.sh` retain the
module-local reproducibility path.

The handwritten client exposes typed `Stop`, `SetLocation`, `RenameFile`,
`RenameFolder` and `Delete` wrappers. Each wrapper validates bounded UTF-8
wire text and sends one explicit torrent hash; empty or pipe-separated values
cannot widen a request to all torrents. `SetLocation` accepts a containing
directory because qBittorrent performs the parent-directory move. The root
adapter remains responsible for deriving that directory from an approved
content target, collision/scope checks and complete read-back.

`Delete` is metadata-only. Its boolean parameter preserves the root control
port shape, but `Delete(..., true)` returns typed invalid-input before login or
dispatch. The only deletion form value emitted by this client is
`deleteFiles=false`; there is no payload-delete helper.

Control requests reuse the module's cookie SID session, origin and referer
headers, redirect refusal, context-bound deadlines, bounded response reads,
status classification and sanitized `UpstreamError` values. A 401 or 403
invalidates the selected session and returns without retrying the mutation.
HTTP 409 maps to the typed conflict outcome. A control response succeeds only
for HTTP 200 with the exact upstream `Ok.` body, so an accepted-but-malformed
response remains unknown and requires later reconciliation.

No root package, domain type, port, adapter, storage or workflow package was
imported. The root runtime does not consume these new write methods yet; live
qBittorrent capability and product-version evidence remain separate gates.
No live service, credential, tracker coordinate, private inventory, media
payload or upstream mutation was used.
