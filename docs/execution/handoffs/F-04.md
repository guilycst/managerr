- Intended result and capability limits: `Placer` implements only the frozen `ports.FilesystemActionPort` copy and hardlink methods. Copy requires an exact validated manifest, source identity and strong SHA-256 evidence, checks all destination collisions before mutation, uses descriptor-relative no-follow access, exclusive adjacent staging, bounded copying, data and parent synchronization, atomic no-replace publication and final path read-back. Existing equal content is `already_satisfied`; unequal content is a conflict and is never overwritten. Hardlink accepts regular files only, proves object identity, reports cross-device/unsupported operations and never falls back to copying. Future move, rename, trash, restore and delete operations return `ErrUnsupported` in this lane.
- Changes completed / remaining: completed Unix descriptor-relative and portable fallback filesystem helpers, exact directory child expansion and source stability checks, root confinement, per-file effects, optional journal append, publication/journal `UncertainError`, read-only copy/hardlink reconciliation, context cancellation checks and synthetic fixtures. The follow-up revalidates every approved directory's exact child set after publication, bounds copy buffers and stage names, handles short writes and zero-value clocks safely, and keeps cleanup limited to directories created by the operation. Reconciliation verifies the destination path visible from the configured root; copy recovery can prove an applied destination from the approved digest even if the source is later unavailable. Non-Unix writes fail closed because the target-specific descriptor-relative no-follow guarantee is unavailable. Durable executor wiring and storage-specific effect persistence remain W-02/F-04 integration work.
