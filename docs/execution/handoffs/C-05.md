The root generation path now validates all committed generated artifacts and
fails if an expected artifact is missing. It generates the root and UI OpenAPI
bindings from the root contract, qBittorrent's generated client from its own
OpenAPI contract using the pinned oapi-codegen tool in the tools module, and
NZBGet's generated DTOs/wrappers using the local
`tools/internal/nzbgetgen` generator with `-mod=readonly`. The nested steps
write into the modules in `--write` mode and generate into a temporary directory
for `--check`, so reproducibility checks do not modify the checkout or fetch a
versioned tool at runtime.

The CI matrix now runs root, UI, tools, qBittorrent and NZBGet as separate Go
module jobs. Every job downloads and verifies its own module, discovers its
packages with `go list ./...`, and fails on an empty package set instead of
silently skipping tests or vet. Generation, API/Vacuum, lint, architecture and
aggregate guardrail jobs include the two nested module manifests in their cache
and dependency setup.

`check-lint.sh` runs the pinned golangci-lint tool independently for all five
modules. Its architecture phase retains the existing root/UI/adapters/domain/
ports check and adds a standalone-client boundary check: client Go files cannot
import Mastarr root packages, Mastarr internal packages, or a different client;
imports within the same client remain valid. `tools/internal/nzbgetgen` remains
outside that client scan and passes the tools-module checks. The fast guardrail
path invokes the architecture-only mode, preserving its focused root/UI tests;
CI runs the full five-module test/vet/module-verification matrix.

No `go.work`, local replace directive, generated-output change, client source
change, shared contract change, credential, private coordinate, live service,
release or deployment was added.
