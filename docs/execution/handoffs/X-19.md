## Product result

Product commit: `a03066b4923cb51d4797bdd40eaedc3dad9305b3`
(`feat(arr): migrate read adapter to standalone clients`). The root adapter now
constructs the selected standalone client and translates its public normalized
observations and typed upstream errors into the existing Mastarr ports. No
generated upstream DTO, generated package, upstream response body or client
module type crosses the adapter boundary.

The root module consumes both independently published clients without a local
`replace` directive or `go.work` file:

- `github.com/guilycst/mastarr/clients/sonarr`
  `v0.0.0-20260915230044-873e53ef6729`, origin commit
  `873e53ef67292549bcd3e42f8246d10c81496132`;
- `github.com/guilycst/mastarr/clients/radarr`
  `v0.0.0-20260915230044-873e53ef6729`, origin commit
  `873e53ef67292549bcd3e42f8246d10c81496132`.

The native translation path covers the standalone contracts' read surfaces:

- Sonarr series catalog, nested episode and episode-file observations,
  Radarr movie catalog and movie-file observations;
- root-folder and quality-profile options;
- native manual-import preview reads, including exact path mapping, movie or
  series identity, episode associations, download identity and native
  rejection evidence;
- import read-back for the selected movie or series, with incomplete identity,
  path and file evidence retained as a sanitized unknown result;
- connection-scoped external identities and the existing local bounded cursor,
  snapshot revision, overlap and partial-coverage semantics.

The root adapter remains the translation and policy boundary. It maps remote
absolute paths through the configured connection mapping, binds catalog and
preview evidence to the requested connection, preserves provider IDs and
episode associations, and keeps all filesystem and workflow decisions outside
the standalone modules. API-key transport, redirect refusal, request
deadlines, bounded decoding and sanitized HTTP errors stay inside the nested
modules. A translated `context.Canceled` or `context.DeadlineExceeded` is
returned with its context identity intact.

The legacy root decoder remains a narrow compatibility fallback for old
synthetic response shapes that the standalone contracts intentionally reject.
Transport errors and explicit incomplete import observations never fall back to
that decoder. This preserves existing partial-evidence behavior while native
strict responses use the standalone typed boundary.

Lookup and history reads, and the detailed reprocess-preview bridge, remain on
the existing root compatibility transport because X-15 and X-16 intentionally
do not publish lookup/history/reprocess operations. The root path preserves
their existing pagination, strict mapping and rejection behavior; adding those
operations to the standalone contracts is a later reviewed extension. The
existing reprocess preview continues to be read-only and no Arr command or
import execution endpoint is called by this lane. Native registration and
import writes remain outside X-19 and are not enabled.

Synthetic fixtures were updated only with native fields required by the
standalone strict contracts: movie/series paths, root-folder accessibility,
episode file identity and manual-import candidate names/sizes/associations.
The new `native_test.go` fixture coverage proves typed 429/401/502 translation
without URL or API-key leakage, Sonarr downloaded-folder preview query
semantics without an accidental `seriesId`, and connection-scoped identity
preservation. Existing fixture tests continue to cover lookup/history,
subtitle and episode mapping, reprocess evidence, redirects, bounds and
read-only/no-command behavior.

No live Arr service, credential, private endpoint, media inventory, filesystem
path or upstream mutation was used.
