## Product result

Product commit: `1a9eb570fa434668c5bfff11b0d2f54180ad1a49` (`fix(qbittorrent): enforce complete responses and cancelable auth`).

The strict response decoder now enforces every member required by the frozen
OpenAPI `TorrentInfo`, `TorrentProperties`, `TorrentFile` and `Category`
schemas. Presence is checked independently of decoded Go zero values, so
legitimate zero and false values in complete fixtures remain valid while any
missing required member or null required value is rejected. Null top-level
responses, array elements and category-map values are rejected before
normalization, and malformed responses return no partial slice or map.

Authentication now coordinates through a context-selectable single-flight
result. One goroutine performs the login, waiting `Login` and read callers can
return their own `context.Canceled` or deadline immediately, and a canceled
caller cannot take the authenticated fast path and return nil. Expired-session
reauthentication, the fast authenticated path and one active login remain
intact.

Inventory validation now tracks canonical supported identities across each
complete response. Exact and mixed-case duplicates of 40-character v1 or
64-character v2 hashes reject the whole observation; distinct v1/v2 identities
pass and the accepted spelling is retained in normalized records.

README and adversarial tests document and exercise the new boundaries. No
qBittorrent mutation route, root-module import, live service, credential,
private coordinate, media payload, release or deployment was used.
